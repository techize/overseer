# End of day Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An End of day button that runs the notes folder's index and split scripts, adds Overseer's own log checks and gaps, and shows a draft of the day's hours per epic to edit and approve; Approve writes the time log note and the `jc push` allocation file, and sends nothing.

**Architecture:** A new daemon module `eod` turns the split script's JSON and today's log checks into a `DayDraft`, keeps the last split by draft id, and writes the two files on `SaveDay`. The server answers both requests from a task. The app shows the draft in an overlay built like the palette; `overseer ctl eod` prints it.

**Tech Stack:** Rust workspace (overseer-proto, overseer-daemon, overseer, overseer-gui on gpui 0.2.2), serde/serde_json, tokio.

**Spec:** `docs/superpowers/specs/2026-11-26-end-of-day-design.md`

## Global Constraints

- Public repo: invented names only in code, tests, docs and commits (DEMO-n tickets, demo-api, demo@example.test). No em dashes anywhere. No emojis in commits.
- Nothing leaves the machine: no task runs `jc push` or any tracker call.
- Hours are whole quarter hours, held as `u32` quarters; totals are exact.
- Each command is killed after 180 seconds and runs with the login-shell environment (`BaseEnv`), as `bd_command` does.
- New proto fields take `#[serde(default)]`; new enums get an `#[serde(other)] Other` variant.
- Copy fixed by the spec: `Running the checks...`, `Discard your changes to the hours?`, `The allocation file for today already exists (it may have been pushed). Replace it?`, `Run the checks again`, `Approved at HH:MM`, `# Time log YYYY-MM-DD`, `from sessions`.
- Config defaults (verbatim):
  - `eod_index_command = ["python3", "Claude/tools/session-index.py"]`
  - `eod_split_command = ["python3", "Claude/tools/day-minutes.py", "--date", "{date}", "--out", "{out}"]`
  - `eod_time_log = "06-Daily/{yyyy}/{mm}-{Month}/{yyyy}-{mm}-{dd}-time-log.md"`
  - `eod_allocation_file = "~/.jira-clockify/allocations/{yyyy}-{mm}-{dd}.json"`
  - `eod_target_arg = ["--target", "{hours}"]`
- The day's target can be changed (the user books 9 hours some days): a target set in the overlay or by `ctl eod --target` re-runs the split with `eod_target_arg` added, `{hours}` filled with the target in hours (`9`, `8.75`).
- Before the full clippy and test runs, `touch crates/*/src/lib.rs`. Shared cargo target; never `cargo clean`.

## Review Focus

1. The split script exits non-zero having written nothing to `{out}`: the draft has the FATAL line and the stdout `note:` lines as problems, no epics, `split_ok == false`. (Task 3, `a_fatal_split_gives_problems_and_no_hours`.)
2. `SaveDay` with an id from an earlier draft after Run again: refused with `Run the checks again`, nothing written. (Task 4, `a_stale_id_is_refused`.)
3. A missing script file under the notes folder (a fresh machine): a problem naming the file, the split skipped, no crash. (Task 3, `a_missing_script_is_a_problem`.)
4. Today's allocation file already exists: `DayExists` with both paths unless `replace`, and the file is untouched. (Task 4, `an_existing_file_needs_replace`.)
5. Editing an epic below zero or past the target: the editor never goes below 0, and Approve stays off until the total is exactly the target. (Task 6, `the_editor_steps_in_quarters_and_gates_approve`.)

### Task 3: Building the draft (pure)

**Files:**
- Create: `crates/overseer-daemon/src/eod.rs` (declare `pub mod eod;` in lib.rs)

**Interfaces:**
- Consumes: Task 1 types; `session_logs::{find_logs, read_logs, problems, Run, local_minutes}`; `DayView::gaps`.
- Produces:
  ```rust
  pub struct Split { pub raw: serde_json::Value, pub target_quarters: u32, pub epics: Vec<EpicHours>, pub tickets: Vec<TicketMinutes>, pub fit: Option<String>, pub problems: Vec<DayProblem> }
  pub fn read_split(json: &str, notes: &Path) -> Result<Split, String>
  pub fn failed_split(code: i32, stdout: &str, stderr: &str, notes: &Path) -> Vec<DayProblem>
  pub fn missing_script(cmd: &[String], notes: &Path) -> Option<DayProblem>
  pub fn fill_command(cmd: &[String], date: &str, out: &Path, target: Option<(&[String], u32)>) -> Vec<String>  // target: (eod_target_arg, quarters), appended with {hours} filled
  pub fn log_problems(day: &DayView, notes: &Path, home: &Path, patterns: &[String]) -> Vec<DayProblem>
  pub fn draft(id: u64, day: &str, split: Result<Split, Vec<DayProblem>>, mut extra: Vec<DayProblem>) -> DayDraft
  ```
  Rules (from the spec's Decisions and Details):
  - `read_split`: hours to quarters by `(h * 4).round()`; `derived_hours` per epic is the sum of `ticket_minutes` whose `ticket_epic` is that epic, over 60; `tickets` per epic from `ticket_epic`; each `unknown_times` slug and `bad_times` entry (slug is the text before ` (`) becomes a problem with `path` set to `Sessions/<slug>.md` only when that file exists under `notes`.
  - `failed_split`: the stderr line starting `FATAL` first (else the last 5 stderr lines), then each stdout line starting `note: `, with slug links as above when the note starts with a slug.
  - `missing_script`: the first element after the program not starting with `-`, if relative and missing under `notes`, gives `<file> is missing in the notes folder; set eod_split_command` (or `eod_index_command`; take the key name as a parameter if needed).
  - `fill_command` replaces `{date}` and `{out}` in every element.
  - `log_problems`: one `Run { slot, started: first, ended: last, worked_until: None }` per stretch; `problems(&read_logs(&find_logs(..)), start_min, end_min, same_day)`; each problem text prefixed with the slot name and `path` set to the first log found, `slot` always set. Plus one problem per gap span: `<slot> has no log for HH:MM-HH:MM`, `slot` set.
  - `draft` puts the split's problems after `extra` (index and log problems first); `split_ok` is `split.is_ok()`.

- [ ] **Step 1: Write the failing tests** in eod.rs, with fixture JSON shaped like the script's (`date`, `target_hours: 7.5`, `epics`, `derivation` with `ticket_minutes`, `ticket_epic`, `fit`, `unknown_times`, `bad_times`, `raw_minutes`), DEMO-n keys only, in a `tempfile` notes folder:
  - `a_clean_split_reads_epics_and_tickets`: target 30 quarters, epic quarters from hours, `derived_hours` summed from tickets, `raw` keeps `raw_minutes`.
  - `unknown_and_bad_times_link_to_their_logs`: a slug with a file gets `path == Some("Sessions/<slug>.md")`, one without gets `None`; `"demo-slug (10:00-09:00)"` parses to `demo-slug`.
  - `a_fatal_split_gives_problems_and_no_hours`: `failed_split(1, "note: demo-a has no start/end, contributes nothing; cover it in the BAU gap\n", "FATAL DEMO-9 has no epic\n", ..)` gives the FATAL first then the note; `draft(.., Err(p), vec![])` has `split_ok == false` and no epics.
  - `a_missing_script_is_a_problem`: `["python3", "Claude/tools/day-minutes.py", "--out", "{out}"]` in an empty folder gives a problem naming the file; with the file present gives `None`; `["demo-split"]` (absolute or bare program, no script arg) gives `None`.
  - `commands_fill_date_and_out`, and with `Some((&["--target", "{hours}"], 36))` the result ends `--target 9`; 35 quarters gives `8.75`.
  - `log_problems_name_the_slot_and_the_gaps`: a `DayView` with one ended stretch for slot 2 and no logs gives `S2: no session log was written` with `slot == Some(2)`, and a Gap span gives `S2 has no log for 10:00-10:30`.

**Interfaces:**
- Consumes: Task 2 config, Task 3 functions, `TimelineService::current`, `BaseEnv`, `brain::paths::fill_template(t, now, 0, "")`.
- Produces:
  ```rust
  pub struct EndOfDay { /* cfg pieces, env, timeline, next id, last: Mutex<Option<Stored>> */ }
  impl EndOfDay {
      pub fn new(cfg: &Config, home: PathBuf, env: BaseEnv, timeline: Arc<TimelineService>, tmp: PathBuf) -> Arc<Self>;
      pub async fn run(&self, now: i64, target_quarters: Option<u32>) -> DayDraft;  // Some only when eod_target_arg is non-empty; else ignored
      pub fn save(&self, id: u64, hours: &[(String, u32)], replace: bool, now: i64) -> Response;
  }
  pub fn time_log_text(d: &DayDraft, hours: &[(String, u32)], approved_at: &str) -> String
  pub fn allocation_json(raw: &serde_json::Value, d: &DayDraft, hours: &[(String, u32)]) -> serde_json::Value
  ```
  - `run`: when `notes_refused` is set or `eod_split_command` is empty, return a draft with `split_ok == false` and one problem saying why (naming `eod_split_command`). Otherwise run the index command (skipped when missing, a problem when it fails), then the split with `{out}` under `tmp` (a fresh name per run, removed after reading), read it, add `log_problems`, store `Stored { id, raw, draft }`, return the draft. 180 s limit each.
  - `save`: refuse unless `id` is the stored one (`Run the checks again`); refuse unless the hours' sum equals `target_quarters` and every key is one of the draft's epics; build both paths; if either exists and `!replace`, return `DayExists`; else write the note (create parent folders) and the allocation file (epics with 0 left out, hours as `quarters / 4`), and return `DaySaved` with `push` = `jc push <allocation> --date-str <day> --non-interactive`. Empty `eod_allocation_file` writes only the note, `allocation` and `push` None.
  - `time_log_text`: `# Time log YYYY-MM-DD`, a hours table (epic, summary, hours, tickets), a minutes-per-ticket table, an open problems list (or none), `Approved at HH:MM`.

- Produces:
  ```rust
  pub struct Hours { pub target: u32, pub rows: Vec<(String, u32)>, edited: bool }
  impl Hours {
      pub fn from_draft(d: &DayDraft) -> Hours;
      pub fn step(&mut self, i: usize, up: bool);   // a quarter, never below 0
      pub fn total(&self) -> u32;
      pub fn left(&self) -> i64;                    // target minus total
      pub fn can_approve(&self, split_ok: bool) -> bool;
      pub fn edited(&self) -> bool;
  }
  pub fn quarters_text(q: u32) -> String;           // 29 -> "7.25"
  pub enum EodEvent { Closed, OpenSlot(SlotId), OpenPath(PathBuf) }
  ```
  The day's target has its own − and + (a quarter each, never below a quarter); changing it sends `EndOfDay { target_quarters: Some(q) }` at once, and Run again sends the target the user set (None until they change it). The buttons are off when the daemon reports the target cannot be changed (`DayDraft.target_fixed`, set by Task 4 from an empty `eod_target_arg`).
  The view: on open shows `Running the checks...` and sends `EndOfDay` from `cx.spawn`. Problems as rows, each clickable to its slot or file. Ticket minutes read-only. Epic rows with − and + and the derived hours `from sessions`. A header `7.50 of 7.50 h` or `0.25 h left to place`. Buttons Run again (asks `Discard your changes to the hours?` first when `edited()`), Approve (off unless `can_approve`), Close (Escape). On `DayExists` it asks the replace question, then sends `SaveDay` with `replace: true` on yes. On `DaySaved` it shows both paths and the push command with a Copy button.
